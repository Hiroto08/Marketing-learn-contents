# 週次ブロードキャスト（メーリスの定常配信）

実世界の対応役割：ニュースレター担当。
目的：**集めたリストに週1で届けて、動画へ戻す（＝視聴シグナル）＋リストを温める**。収益化戦略§5-2／`docs/mailing-list-plan.md`§3。
原則：**短く・流し読み前提。1通1リンクを主役に。** 送信は常にKit側で人間が最終確認して送る。

## 配信リズム
- **動画公開に同期して週1**（例：土曜公開→日曜配信）。**開始はEP07から**（EP01〜06は既に公開済みのため、週次配信の第1号はEP07）
- 2種類を交互に回す：
  - **A. 新作ダイジェスト**（動画公開週）＝本スキルの主対象
  - **B. 深掘り/Tips**（動画が無い週）＝過去回の1テーマや実務の小ワザ（草稿は手書き or 過去script流用）

## 手順（A. 新作ダイジェスト）
1. 草稿を生成：
   ```bash
   python3 _tools/repurpose/make_broadcast.py --episode <ep_dir> [--note <note記事URL>]
   ```
   → `_deliverables/broadcast/ep<NN>_*.md`（件名＋本文。動画URLは docs/upload-status.md から自動解決）
2. **軽く推敲**（機械生成なので）：件名は開封したくなるか／冒頭3行で引き込めるか／本文が長すぎないか（目安 本文400〜700字）／リンクは動画1つが主役か
3. **Kitで送信**：Kit → **Broadcasts → New broadcast** に件名・本文を貼る → プレビュー → **Send now / Schedule**（曜日時刻固定）。**送信前に自分宛テスト送信**で見た目・リンク・迷惑メール入りを確認
4. 送信後、`_deliverables/broadcast/` の草稿をコミット（記録として）

## 品質チェック（送る前に全て）
- [ ] 件名が具体的で開封動機がある（「今週の動画」だけにしない）
- [ ] 冒頭がフック（結論やCMのような入りにしない）
- [ ] 主役リンク＝動画1つ。オプトイン/note導線は従（詰め込みすぎない）
- [ ] テスト送信で表示・リンク・到達（迷惑メール）を確認
- [ ] 配信停止リンクが入っている（Kitが自動付与）

## やってはいけないこと
- 動画の全内容をメールに書く（メールは"さわり"だけ。続きは動画で回収）
- 毎回同じ件名・同じ書き出し（開封率が落ちる）
- Kitの送信を自動化しようとしてポリシー/到達率を壊す（送信は人間の最終確認を通す）

## 引き継ぎ
→ ユーザー（Kitで送信）／到達率・開封率が悪ければ `docs/mailing-list-plan.md` §5 のKPIで見直し
