全ルールは「数値基準＋検証手順」で書かれている。感覚で判断せず、下のチェックを機械的に通すこと。

## 1. パッケージング先行（台本を書く前に必ずやる）

script.md の `## 動画基本情報` の直後に以下のブロックを**必ず**作る（templates.md参照）：

```markdown
### パッケージング（台本より先に決定）
| 項目 | 内容 |
|------|------|
| 検索KW | （2〜3語の学習意図KW。例：STP分析 やり方） |
| タイトル案A | （25文字以内） |
| タイトル案B | （25文字以内） |
| タイトル案C | （25文字以内） |
| 採用タイトル | （A/B/Cのどれか） |
| サムネ文字 | （6〜9文字＋数字1つ。タイトルと同文言は禁止） |
| サムネの約束 | （サムネ/タイトルが視聴者に約束したこと。S1〜S2で必ず回収する） |
```

**タイトルの合格条件（全て満たす）**：
- [ ] 25文字以内（`len()`で確認。全角換算）
- [ ] 主語が視聴者の得・損・数字（フレームワーク名が主語なら不合格）
- [ ] 「第N回」「〜とは」「超基本」「入門」を先頭に置いていない（KWとしての「〜とは」は後半・【】内なら可）
- [ ] 数字・金額・損失回避（「〜すると損」「9割が」）のいずれか1つ以上を含む
- [ ] 検索KWの語をタイトル前半に自然に含む
- [ ] 架空の事例・数字を実在のように見せていない（ファクトチェック方針）

**NG→OK例**：
- ✗「第2回：誰に何を売る？『3C分析』と『STP分析』の超基本」
- ○「売る相手を間違えると全部ムダになる話【STP分析のやり方】」

## 2. 動画構造 v2（18スライドへの割り付け）

| スライド | 役割 | ナレーション必須要素 |
|---------|------|--------------------|
| S1 | コールドオープン | ビジュアルアンカー（衝撃の数字/対比）＋違和感フック。挨拶・回数の読み上げ禁止 |
| S2 | 約束（4P） | Promise→Plan（3点）→Proof（数字）→Picture ＋ **メインのオープンループ**を張る |
| S3〜S6 | ケーススタディ前半 | 1つの実例を深掘り（例を細切れに変えない） |
| S7 | リフック①（〜3分地点） | 意外な数字・常識の反転・失敗の暴露のどれか |
| S8〜S11 | 原則の抽出 | 事例→理論の一般化。途中にミニ問いかけ |
| S12 | リフック②（〜6分地点） | 2つ目の反転／メインループの部分回収 |
| S13〜S15 | 適用 | 冒頭の事例に原則を当て直す＋視聴者への翻訳（As-Is→To-Be） |
| S16〜S17 | 回収とまとめ | メインループ完全回収。「明日やること1つ」で締める |
| S18 | 次への開ループ | 未解決の問いを1つ残す＋登録CTA（終了画面用に新情報を出さない静止構成） |

- 具体例は必ず「As-Is（元々どうだったか）→ To-Be（何をどう変えたか）→ 結果の数字」の3点セット（EP07 S16の形式）
- 毎回「エピソード固有の一次情報」（独自図解・日本の数字・実名事例）を最低1つ。使い回しテンプレ図解だけの回は不合格

## 3. ナレーション検査（機械チェック）

台本完成後、**統合検証コマンドを必ず実行**する。FAILが出たら書き直してから次の工程へ：

```bash
python3 _tools/checks/verify_episode.py <episode_dir> --no-browser
```

このコマンドの「3) ナレーション品質」が検査する基準（執筆時に意識する数値）：
- S1の最初の2文に禁止句（「のテーマは」「さっそく始めましょう」等）が無い
- 「そして」「また、」合計2回以下（接続は しかし/ところが/実は/だから/つまり）
- 問いかけ（〜と思いますか/でしょうか/考えてみてください/ませんか）3回以上
- 逆接・因果接続詞 6回以上
- S18に未解決の問い（開ループ）がある

このチェックはあくまで下限。**数値を満たしても、S2で張った問いがS13以前に完全回収されていたら書き直し**（オープンループの目視確認だけは人力/モデルで行い、script.md制作メモに「主ループ：S2『◯◯』→S16回収」と明記する）。

VOICEVOX読み・略語は従来どおり [narration-rules.md](narration-rules.md) の検査を併用。

## 4. スライドのテンポ検査（STEPS密度）

**基準：各スライドのSTEP数 ≥ そのスライドの音声秒数 ÷ 7（切り上げ）、かつ15秒超の無変化区間なし。**

slide.html完成後、**統合検証コマンドで検査**する（「4) STEPS密度」「6) タイポグラフィ」「7) ブラウザ描画」が該当）：

```bash
python3 _tools/checks/verify_episode.py <episode_dir>
```

- STEPを増やす手段：要素の順次出現（1行ずつ）、ハイライト移動、タグの段階表示、グラフの段階伸長。**新しいCSS/JSエンジンを作らない**（既存の rv-fade/rv-up/rv-scale/rv-pop の組み合わせで実現する）
- サムネに使える「絵になる1枚」（大きな数字・対比・Before/After）をS1またはS7に必ず置く
- 改行・空白の品質基準は [design-system.md](design-system.md) の「タイポグラフィ基準」（t-xl≤14字/行・明示的`<br>`・行頭禁則など）

## 5. description.md のSEO規則

- 冒頭2行（折りたたみ前に見える部分）に検索KWと視聴メリットを含める
- チャプター名にサブKWを入れる（例「ペルソナの作り方3ステップ」）
- タイトル・冒頭2行・チャプターの3か所でKW表記を統一する（表記ゆれ禁止）
- 「第N回」表記は概要欄の**シリーズ案内ブロック内のみ**可（タイトル・冒頭2行では使わない）

## 6. Shorts台本（L3のとき各回3本）

`<episode_dir>/shorts.md` に3本分を書く。1本の構成（45〜60秒）：

1. 0〜3秒：本編と同じビジュアルアンカー（数字/対比）を一言で
2. 〜40秒：1論点だけ完結に（本編S7のリフック素材／ミニ問いかけ素材／まとめの1アクション から各1本）
3. ラスト：「◯◯の全体像は長編で解説しています」の橋渡し

タイトルはKW型・質問型（例「ペルソナの作り方で9割がやる失敗」）。
