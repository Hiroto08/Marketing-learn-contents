# ナレーション・TTS（VOICEVOX）ルール

> **本ファイルは「読み方（TTS）」のルール。台本の構成・書き方（コールドオープン、オープンループ、
> 接続詞監査、問いかけ密度などの維持率ライティング）は [retention-packaging.md](retention-packaging.md) §2〜3 が正**。
> 台本完成時は両方の検査（維持率検査＋読み方検査）をPASSさせること。

## プロジェクト概要

- コース名：AI時代のマーケティング・ラボ
- TTS エンジン：VOICEVOX（http://127.0.0.1:50021）
- 話者：11 = 玄野武宏 ノーマル
- 再生速度：1.1x

## ナレーション構造

```js
const NARRATIONS = [
  // S1
  `1段落目のテキスト。文末は必ず句読点で終わる。\n2段落目のテキスト。`,
  // S2
  `...`,
];
```

- スライド1枚につき1エントリ（`NARRATIONS[i]` = スライド `i+1` 対応）
- 段落区切りは `\n`（改行1個）
- 文末は `。` `！` `？` のいずれかで終わること（TTSが文単位で合成する）
- 1段落 = 2〜4文程度が理想。長すぎると息継ぎが不自然になる
- `script.md` の `**ナレーション：**` ブロックと `NARRATIONS[N-1]` は**文字単位で完全一致**させる

## 尺の目安

| 指標 | 値 |
|------|-----|
| 実効読み上げ速度 | 約 6.7〜6.9 字/秒（1.1x時） |
| 1エピソード目標 | 8〜10分 |
| 必要文字数（目安） | 3,200〜4,150字 |
| `TOTAL_SECS` 設定 | 700〜750 sec |
| スライド数 | 18枚（1スライド1コンセプトで細分化） |

計算式：`推定秒数 = 総文字数 ÷ 6.8 + (段落数 × 0.45) + (文数 × 0.28)`

これは**ビルド前の推定値**。実際の音声合成後の尺は数%〜十数%ずれることがあるため、
動画をビルドした場合は必ずffprobeで実測し直す（SKILL.mdの「動画ビルド後のタイムスタンプ修正」参照）。

## VOICEVOX 訓読みルール

VOICEVOXは漢字を音読みしがちなため、文脈に合わせてひらがなに置き換える。

### 必須置換リスト

| 漢字表記 | 誤読 | 正しい読み | ひらがな置換後 |
|----------|------|-----------|--------------|
| 〜方（やり方・考え方・作り方・使われ方） | ほう | かた | 〜かた |
| すべての方 | ほう | かた（人・方法） | すべてのかた |
| 重なる | じゅうなる | かさなる | かさなる |
| 他の〜（ほかの〜） | た | ほか | ほかの〜 |
| 作り手・〜作り手から | しゅ（作りしゅ） | て | 作りて（作りてから） |
| 深掘り | ふかほり | ふかぼり | ふかぼり |

### 条件付き置換

| 漢字表記 | 置換条件 | 例 |
|----------|---------|-----|
| 方（かた） | 「人」「やり方」文脈 | すべてのかた、作りかた |
| 方（ほう） | 「一方」「方向」文脈 | **置換しない**（一方・方向・方針はそのまま） |
| 的（てき） | 接尾辞（具体的・客観的・効果的など） | **置換しない** |
| 的（まと） | ダーツの的・対象を指す場合 | まと（例：「まと全体」「まとの中心」） |

### スキャン用チェックポイント

ナレーション完成後、以下を必ずチェックする：

```python
import re

checks = [
    (r'重なる', 'かさなる に置換'),
    (r'(?<![一方方向方針])方(?![向針法程])(?![をにはがもでのと])', '「かた」文脈か確認'),
    (r'他の', 'ほかの に置換'),
    (r'(?<!具体|客観|効果|積極|消極|相対|絶対|主観|戦略|論理|感情|一般|特定|直接|間接)的(?!に|な|だ)', '「まと」文脈か確認'),
    (r'作り手', '作りて に置換（しゅ誤読防止）'),
    (r'深掘り', 'ふかぼり に置換（ふかほり誤読防止）'),
    (r'と問うと、', '読点を除去 → と問うと（前の語と繋げる）'),
]
```

## VOICEVOX 複合語イントネーション・略語

「3C分析」「STP分析」のような**略語＋名詞**の複合語は、OpenJTalkが単語境界で分割して
不自然な上昇イントネーションになる。

**対策：`_tools/video/make_video.py` の `ABBR_MAP`/`COMPOUND_DICT` に登録する**

```python
# _tools/video/make_video.py 内（現状の登録例）
ABBR_MAP = {
    "AMA":  "エーエムエー",  "SNS":  "エスエヌエス",  "AI":   "エーアイ",
    "PR":   "ピーアール",    "HBR":  "エイチビーアール", "HBS": "エイチビーエス",
    "JTBD": "ジェイティービーディー", "STP": "エスティーピー",
    "KPI":  "ケーピーアイ",  "CPA":  "シーピーエー",   "LTV":  "エルティーブイ",
    "CTR":  "シーティーアール", "CVR": "シーブイアール", "ROI":  "アールオーアイ",
    "ROAS": "アールオーエーエス", "SEO": "エスイーオー", "CRM":  "シーアールエム",
    "UGC":  "ユージーシー",
    "3C":   "サンシー",        "4P":   "ヨンピー",      "4C":   "ヨンシー",
    "AIDMA": "アイドマ",       "AISAS": "アイサス",
    "USP":  "ユーエスピー",
    # …CAC/AB/CTA/EC/GA4/URL/VWO/RAG/NPS/CSV なども登録済み（最新は make_video.py が正）
    "5A":   "ファイブエー",   # ×ごあんぺあ（5アンペアと誤読）
    "SaaS": "サース",         # ×サーエス（大文字小文字混在のまま一致＝case-sensitive）
}

COMPOUND_DICT = {
    # surface（ABBR_MAP変換後のカタカナ表記）: (pronunciation, accent_type)
    "サンシー分析":        ("サンシーブンセキ", 5),       # 3C分析
    "エスティーピー分析":  ("エスティーピーブンセキ", 6),  # STP分析
    "ヨンピー分析":        ("ヨンピーブンセキ", 4),        # 4P分析
    "ヨンシー分析":        ("ヨンシーブンセキ", 4),        # 4C分析
    # ↓ イントネーションではなく「読み」そのものを上書きする用途にも使う
    "一方向":              ("イチホウコウ", 0),            # いちほうこう（×いっぽうこう）
    "高級品":              ("コウキュウヒン", 0),          # こうきゅうひん（×こうきゅうしな）
    "三方良し":            ("サンポウヨシ", 4),            # さんぽうよし（×さんぽういし）
}
```

> **priority は 10 を使う（`seed_user_dict()` で設定済み）。** 「一方向」「高級品」のように
> システム辞書に強い既定読みがある語は、priority 9 以下だとユーザー辞書が無視されて誤読のまま。
> 長音は「ー」より母音字（コウ＝コー、ヒン）で書くと確実に適用される（`イチホーコー`✕→`イチホウコウ`◯）。

**新しいエピソードのナレーションを書いたら、必ず本文中の英字略語を `ABBR_MAP` のキーと照合する。**
未登録の略語があれば、既存パターンに従って正しいカタカナ読みを追加する（例：`"CAC": "シーエーシー",`）。
2文字略語（"AI"など）を追加する際は `clean_for_tts` の正規表現（`(?<![A-Za-z])abbr(?![A-Za-z])`）が
誤爆しないか確認する。

**新しい複合語を追加するとき：**

1. VOICEVOX APIで発音を確認する：
   ```bash
   curl -s -X POST "http://127.0.0.1:50021/accent_phrases?text=新語＋分析&speaker=11" | python3 -m json.tool
   ```
2. 現状の分割が不自然なら `COMPOUND_DICT` に追加
3. `seed_user_dict()` が `make_video.py` 起動時に自動登録するので追記だけで有効になる

### 確定済みの誤読修正リスト（全EP共通・再発防止）

過去のEPで実際に誤読が確認され、修正済みの語。**他のエピソードでも同じ語が出たら必ず正しく読ませる**
（登録済みなので新規対応は不要だが、新語が同じパターンに当てはまらないか確認すること）。

| 表記 | VOICEVOX誤読 | 正しい読み | 登録先 | 初出 |
|------|-------------|-----------|--------|------|
| `5A` | ごあんぺあ（5アンペア） | ファイブエー | ABBR_MAP | EP05 |
| `SaaS` | サーエス | サース | ABBR_MAP | EP05 |
| `一方向` | いっぽうこう | いちほうこう | COMPOUND_DICT | EP05 |
| `高級品` | こうきゅうしな | こうきゅうひん | COMPOUND_DICT | EP06 |
| `三方良し` | さんぽういし | さんぽうよし | COMPOUND_DICT | EP06 |
| `D2C` | ディー**ニ**シー（2→に） | ディーツーシー | ABBR_MAP | EP07 |
| `4C` | ヨン**スィイ** | ヨンシー（4Pのヨンピーと韻を揃える） | COMPOUND_DICT | EP07 |
| `Airbnb` | エアブンブ | エアビー | ABBR_MAP | EP08 |
| `QB`（QBハウス） | 分割読み | キュービー | ABBR_MAP | EP02 |
| `QBハウス` | キュ'ウ/ビ'イ/ハ'ウス（3分割） | キュービーハ'ウス（1語） | COMPOUND_DICT | EP02 |
| `3C`（単独） | サンスィイ | サンシー（「3C分析」は複合語登録が先に効く） | COMPOUND_DICT | EP02 |
| `日本中` | にっぽん**ちゅう** | にっぽんじゅう | COMPOUND_DICT | EP02 |
| `顔剃り` | カオ/ソリ（分割） | かおそり（1語） | COMPOUND_DICT | EP02 |
| `遠山正道` | 正道→**せいどう** | とおやま まさみち（人名。全名で登録） | COMPOUND_DICT | EP03 |
| `M&M's` | 記号読み崩れ | エムアンドエムズ | ABBR_MAP | EP08 |

読み監査済みで**登録不要と確認した語**（ネイティブ読みが正しい。audio_query kanaで確認）：
`CM`＝シーエム／`銀座松屋通り店`＝ギンザマツヤドオリテン／`松村謙三`＝マツムラケンゾオ／`ハズキルーペ`＝1語・正アクセント（EP07/EP08 L3時に確認）。

> 数字を挟む略語（`D2C`）は数字が訓読み（に）になりやすい→ABBR_MAPで丸ごとカタカナ指定。
> `「A」「B」「C」`のような引用符の列挙は `clean_for_tts` が `」「`→`、` に変換して
> 無ポーズの連結読みを防ぐ（対応済み）。

> 注意：`一方` 単独（例「手厚い一方で」）は **いっぽう** が正しいのでそのまま。
> 語末の「〜方（かた）」は訓読みルール（上表）でひらがな化、複合語内の特殊読みは COMPOUND_DICT で上書き、と使い分ける。
> ナレーション完成後は VOICEVOX API（`/audio_query` の `kana`）で実際の読みを確認するのが最も確実。

## よくある問題と対処

| 問題 | 原因 | 対処 |
|------|------|------|
| 音声が途中で切れる | 文が句読点で終わっていない | ナレーション末尾に `。` を追加 |
| スライドが短すぎる | ナレーションが少ない | 1スライドあたり150〜250字を目安に追記 |
| 動画が長すぎる | ナレーションが多い | 1エピソード3,200〜4,150字に調整 |
| VOICEVOX誤読 | 音読みデフォルト | 上記置換リストを適用 |
| `VOICEVOX unreachable` | エンジン未起動（コンテナ再起動後） | `/opt/voicevox_engine/.../run` を起動して待機 |
| `playwright install` を促される/ブラウザ無し | バージョン不一致 | `/opt/pw-browsers` をsymlink＋`PLAYWRIGHT_BROWSERS_PATH`指定 |
| `make_video.py` が無い／`_tools`が消えている | ローカルが古い | `git pull` でremoteと同期 |

## 実行環境の前提（コンテナ再起動後に必須）

`.claude/hooks/session-start.sh` がSessionStartフックとして登録されており、コンテナ再起動時に
自動的に環境を復旧する（ffmpeg・Noto CJKフォント・Playwright・VOICEVOX）。

手動で再実行したい場合：

```bash
bash _tools/setup_env.sh
```

個別確認：

```bash
# VOICEVOX起動確認（落ちていたら起動）
curl -s http://127.0.0.1:50021/version || \
  /opt/voicevox_engine/linux-cpu-x64/run --host 127.0.0.1 --port 50021 &
until curl -s http://127.0.0.1:50021/version >/dev/null 2>&1; do sleep 2; done

# Playwrightブラウザは PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers を指定して実行
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers python3 _tools/video/make_video.py ...
```
