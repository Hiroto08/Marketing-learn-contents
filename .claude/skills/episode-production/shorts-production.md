# Shorts制作仕様（流入・発見装置）

根拠：バイラルShortsパターン調査（2024-2026、JP/EN）。長編（本編）とは目的が違うため
別仕様として切り出す——**Shortsは「発見・維持率・回遊」を稼ぐ装置**であり、長編視聴への
送客率は現実には低い（重複視聴者は業界目安で約10%）という前提でゴールを設計する。

## 1. 位置づけとゴール

- Shortsの成功指標は**長編への送客数ではない**。①3秒通過率（離脱防止）②完走率／ループ再生
  ③チャンネル自体の新規リーチ、の3つを主目標にする
- 送客（固定コメント・口頭CTA・概要欄）はCTR5%が健全ラインの「おまけ」。過度な期待をしない
- 1本の長編（8〜9分）から**3〜5本**を切り出す。切り出し元は本編のS7リフック／ミニ問いかけ／
  まとめの1アクション／固有図解、のいずれか1論点＝1本

## 2. 尺・構成（数値基準）

**目標尺：15〜25秒（最大30秒）。1本1メッセージ厳守。長いShortsは最後まで見られない。**

短さが最優先。**冗長な言い回し・接続詞・前置き・言い直し・固有名詞のフルネーム連呼を全部削る**。
「実は」「つまり」「〜なんです」「〜というわけです」「という会社があります」等の水増し表現は禁止。
1情報＝1文で言い切る。迷ったら短いほうを採る。

| 区間 | 秒数 | 内容 |
|------|------|------|
| フック | 0〜2秒 | 数字・断言・否定形・問いかけのいずれか1つ。**最初のフレームは最後のフレームと絵/文言を一致させる**（ビジュアルループ）。挨拶・前置き・社名紹介から入らない |
| 結論先出し | 2〜7秒 | 答えを先に断言する（「要するに◯◯」型。詳細は後回し） |
| 展開 | 7〜17秒 | 論点を**1〜2枚**のカードで具体化（数字・対比を1つだけ）。説明を足したくなったら削る |
| オチ＋ループ＋CTA | 17〜25秒 | 冒頭の一言を再文脈化して締める（ナラティブループ）。同じスライドに送客テロップ「続きは固定コメントへ」を重ねる |

**ナレーション文字数の上限（厳守）：1スライド原則1文・最大35字。全スライド合計150字以内**
（÷6.8字/秒＋間 ≒ 22〜25秒に収まる）。合計が150字を超えたら、必ず文を削るか統合する。

- 3秒通過率の目標：70%以上（合格）／76%以上（優秀）。冒頭は必ず**動きのある要素**を1秒目に置く
  （静止画・ロゴ・挨拶から入るのは離脱要因＝長編のコールドオープン原則と同じ理由）
- スライド枚数：**4〜6枚**（長編の18枚とは別規格。多いほど1枚あたりが薄まるので少なめが良い）

## 3. 縦型9:16デザイン数値基準

キャンバス**1080×1920**。実装は `_tools/shorts_template/vertical_template.html` を必ずコピーして使う
（big styleのkeyframes/rv-*/`.se`初期非表示はエンジンとして不変のまま移植済み。ここを書き換えない）。

| 領域 | 値 | 備考 |
|------|-----|------|
| 上セーフ | 192px | ステータスバー・UI回避 |
| 下セーフ | 400px | キャプション帯・フィード操作ボタン回避。**最重要要素をここに置かない** |
| 左右セーフ | 各48px | タイトルセーフ |
| テロップ位置 | 下セーフの直上（`.caption-zone`） | 中央寄せ・最大2行 |
| テロップ文字数 | 1行15〜18文字・最大2行 | 40字超は自動縮小され読めなくなる |
| 見出し級（`.k-line`） | 88px・Black(900) | design v2.1の見出しBlack規約を継承 |
| 数字級（`.k-num`） | 220px・アクセント色 | フックの主役数字用 |
| 結論語 | キーイエロー`--key:#FFD54F` | 長編と同じ役割分離（`.hi`クラス） |

## 4. 台本ルール（フック・ループ）

- 冒頭フックは以下のいずれか1型（本編のS1コールドオープンと同じ精神、Shorts用に強度を上げる）：
  数字提示／断言・否定形／問いかけ／結論先出し＋カリオシティギャップ
- **ナラティブループ**：オチの一文が冒頭の一文を再文脈化する（例：冒頭「商品は同じ。」→オチ
  「変えたのは商品じゃなかった——商品は、同じ。」）
- **ビジュアルループ**：最終スライドのレイアウト・文言を冒頭スライドに近づけ、ループ再生時の
  継ぎ目を感じさせない（`vertical_template.html`のS1/S末尾で同じ`.k-line`文言を使う等）
- 送客は「続きは固定コメント／概要欄で」を**口頭＋テロップ両方**に必ず入れる（口頭のみ・テロップ
  のみは弱い）
- ナレーションはVOICEVOX読みルール（narration-rules.md）を長編と同様に適用する

## 5. ビルドコマンド

```bash
python3 _tools/video/make_video.py <shorts_html> \
  --out <episode_dir>/shorts_build/short1 \
  --speaker 11 --speed 1.15 \
  --lead 1.2 --intro 0.3 --outro 0.5 --final-outro 1.2 \
  --width 1080 --height 1920 \
  --bgm _assets/audio/bgm_calm_loop.wav --sfx-dir _assets/audio
```

- `--out` は**ディレクトリ**を渡す（`shorts_build/shortN/`）。エンジンは `<dir>/<親フォルダ名>_final.mp4` を書き出す。ファイル名を渡すと入れ子ディレクトリが出来て失敗する
- `--speed 1.15`（長編の1.1よりやや速め。Shortsはテンポ最優先）
- **無音パディングを長編より詰める**：`--intro 0.3 --outro 0.5 --final-outro 1.2`（長編の既定は 0.6/1.0/3.0）。
  Shortsはループ再生前提なので、各スライドの前後の間と末尾の余韻を削って体感テンポを上げる。
  これで台本合計110字が実尺 約22〜24秒に収まる（既定パディングのままだと同じ台本でも28秒超に膨らむ）
- BGM/SFXは長編と同一アセット・同一音量基準（`audio-production.md`）でよい
- ビルド前に VOICEVOX が起動しているか確認（`curl -s http://127.0.0.1:50021/version`）。落ちていたら
  `_tools/setup_env.sh` を実行するか `nohup /opt/voicevox_engine/linux-cpu-x64/run --host 127.0.0.1 --port 50021 &`

## 6. 検証（機械チェック）

```bash
python3 _tools/checks/verify_shorts.py <shorts_html_dir>
```

検査項目：尺30〜45秒／スライド5〜8枚／フックがS1の最初のSTEPに存在／セーフエリア侵犯なし
（Playwright実測）／末尾スライドに送客テロップ（「固定コメント」「概要欄」等）が存在／
冒頭と末尾の文言重複（ループ検定・完全一致でなくてよいが3文字以上の共通語を要求）。

## 7. 公開時チェックリスト

- ハッシュタグ：3〜5個（#Shorts＋ニッチ1〜2＋トレンド/ブランド1）。15個超で全無効化に注意
- タイトル：55〜60文字以内・重要語を先頭
- カバー：Shortsは別画像不可＝動画内フレームがそのままカバーになる。フック直後の
  価値提案フレームが選ばれるよう、S1に太字の要約テキストを焼き込む
- 固定コメントに長編リンク＋一言、概要欄にも本編URL、末尾で口頭CTA — の3点セット必須
- 投稿頻度：初期は1日1本〜週3本を同時刻固定で最低30日継続（質を落として乱発しない）
