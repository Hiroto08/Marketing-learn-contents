# 品質ゲート（合否チェックリスト）

全動画・全記事に適用する。2026-11-10 制定（社長指示・Issue #2）。各ロールのスキルは、この文書の項目番号を参照する。

- **合否は機械検査で決める**。項目はすべて「合格か不合格か」で判定できる形にしてある。不合格が1つでもあれば、ビルド・アップロード・公開に進まない。
- **実施記録を残す**。ビルドのたびに `quality_record.md`（動画ごと）が自動で書かれる。コミットする。
- **旧基準の回**（2026-11-10 より前に台本を書いた回。`_tools/checks/style_legacy.txt`）は、A・T・F を参考表示にとどめる。R（読み）は旧基準の回でも不合格にする。
- 基準を変えるときは、この文書とツールを同じコミットで直す。ツールだけ、文書だけを変えない。

## 0. 1コマンドで全部走らせる

```bash
python3 _tools/checks/quality_record.py <回のフォルダ>     # 全検査を実行し、<回のフォルダ>/quality_record.md に記録
```

`run_episode.sh`・`run_shorts.sh` は、ビルドの前に R・F・A・T を、ビルドの後に R（音声の照合）と記録の作成を実行する。

## 1. 固有名詞と読み（R）— 最優先

道具：`docs/proper-nouns.md`（台帳）、`_tools/checks/proper_nouns.py`、`_tools/checks/check_readings.py`

| 番号 | 合格の条件 | 不合格のときの直し方 |
|---|---|---|
| R1 網羅 | 原稿の固有名詞（人名・企業・商品・地名・媒体）が、すべて台帳にある。固有名詞でない語は一般語リストにある | 台帳に行を足す。読みを確認できない固有名詞は、名前を出さない表現に書き換える |
| R2 確認ソース | 台帳の行に確認日がある。確認日は `proper_nouns.py --verify` が、確認ソースのページに「確認文字列」があるのを見つけた日 | 確認ソース（URL）と確認文字列（ふりがな・ローマ字）を書き、`--verify` を実行する |
| R3 辞書登録 | 漢字の人名が、`make_video.py` の COMPOUND_DICT にある | 読みとアクセントを登録する |
| R4 読みの一致 | 台帳の表記が出る文で、VOICEVOX の読みに台帳の読みが含まれる | COMPOUND_DICT／ABBR_MAP／READING_MAP で直す |
| R5 区切れ | 4字以上のカタカナ語が、文の中で2つのアクセント句に割れない | COMPOUND_DICT に1語で登録する |
| R6 数字の読み | 西暦が4桁で読まれる。①②③ が「ひとつめ・ふたつめ・みっつめ」と読まれる | ツールの不具合なので make_video.py を直す |
| R7 英字の読み | 2字以上の英字の語が、ABBR_MAP か台帳にある | ABBR_MAP に読みを登録する |
| R8 既知の誤読 | 過去に起きた誤読の型（`check_readings.py` の BAD）に当たらない | 辞書で直す。辞書で直らないものは、ナレーションをかなで書く |
| R9 音声と原稿 | ビルド後の `built_readings.json`（実際に音声になった読み）の文が、今のナレーションと1文ずつ一致し、R4〜R8 を満たす | ビルドし直す |
| R10 読みの食い違い | 別の辞書（janome）と VOICEVOX で読みが違う語が、確認済みリスト（`reading_confirmed.txt`）にある | 読みを確かめる。VOICEVOX が正しければリストに足す。間違っていれば辞書で直す |

**確認ソースの決まり**

- 一次ソースの優先順：本人・会社の公式サイト → 出版社の著者紹介（著書の表記）→ 官公庁。
- 漢字の人名は、ふりがなかローマ字が載っているページだけを証拠にする。表記だけのページは証拠にならない。
- 海外の人名・社名で日本語の公式表記が無いものは、訳書の出版社か事典の表記を使い、種別に「二次」と書く。
- 確認できないときは、原稿からその名前を消す（例：u14「アリー」→「あるインフルエンサー」）。

**新しい誤読を見つけたとき**（公開の前後を問わない）

1. `make_video.py` の辞書で直す。
2. `check_readings.py` の BAD に型を足す。
3. `narration-rules.md` の「確定済み誤読リスト」に1行足す。

## 2. 数字と事実（F）

道具：`_tools/checks/check_facts.py`。台本（本編・ケースファイルは script.md、Shorts は shorts.md）に「## 数字の確認」の表を書く。

| 番号 | 合格の条件 |
|---|---|
| F1 網羅 | ナレーションの「数字＋単位」（%・倍・円・ドル・人・件・回・時間 など）が、すべて表の「数字」欄にある |
| F2 2ソース | 各行に URL が2つ以上あり、2つ以上の別のサイトに分かれている。事例の数字でないもの（公開時刻・手順の数）は「対象外：理由」と書く |
| F3 西暦 | ナレーションの西暦も表にある |

- 2つの情報源で数字が食い違うときは、その数字を使わない。両方が一致する言い方（「約」「〜台」）にするか、題材を替える。
- 人の発言を引用するときは、発言の出どころ（インタビュー・著書）を1つめ、それを報じた別の媒体を2つめにする。
- 動画で扱っていない数字について視聴者から聞かれたときは、出どころだけを答える。根拠を推測で補わない。

## 3. 文章の AI 臭さ（A）

道具：`_tools/checks/check_style.py`

| 番号 | 合格の条件 | 対象 |
|---|---|---|
| A1 語尾の連続 | 同じ語尾（です／ます／でした／ました／のです／体言止め…）が4文以上続かない | 本編・ケースファイル |
| A2 「のです」 | 「のです／んです」で終わる文が、全体の10%以下 | 本編・ケースファイル |
| A3 文頭の接続詞 | 同じ接続詞（実は・しかし・つまり・では・そこで・だから・ところが・さらに・ただ・しかも・それでも・そして・一方）で始まる文が、1本で3回まで。Shorts は1回まで | すべて |
| A4 回をまたぐ同じ文 | 過去の回と同じ文（10字以上）が無い。例外は `style_fixed_lines.txt` の1文だけ | すべて |
| A5 文の長さ | 1文が80字以内。文の長さのばらつき（標準偏差÷平均）が0.35以上 | 80字はすべて。ばらつきは本編・ケースファイル |
| A6 対比の型 | 「〜ではなく、〜」が1本で3回まで | すべて |
| A7 繰り返し・定型句 | 1本の中で同じ文（10字以上）が2回まで。定型句（いかがでしたか／意外な事実があります／数字でおさらいします／あらためて問います／〜していきましょう／〜と言えるでしょう／〜ではないでしょうか／結論から言うと／さっそく）が無い | すべて |

- 構成の型（冒頭の問い → 事例 → 原則 → 持ち帰り）は使ってよい。**型を示す文を、毎回同じ言葉で言わない**。これが A4 の趣旨。
- 定型句を新しく見つけたら、`check_style.py` の BANNED に足す。

## 4. テロップ（T）

| 番号 | 合格の条件 | 道具 |
|---|---|---|
| T1 表記ゆれ | 画面に全角の英数字が無い。長音の有無だけが違う語（ユーザ／ユーザー）が混ざっていない | check_style.py |
| T2 画面の数字 | 画面に出る「数字＋単位」が、ナレーションにもある（値で比べる。西暦と次回予告は対象外） | check_style.py |
| T3 画面と音声の文 | テロップ同期型の Shorts は、画面の文＝ナレーションの文（1文＝1要素）。文字は48px以上。`<br>` 以外で折り返さない | verify_shorts.py（検査10・セーフエリア） |
| T4 誤字 | 画面の文字は、ナレーションから機械で作る（Shorts は `build_telop_spec.py`、ケースファイルは `build_case_slide.py`）。手で打ち直さない | 手順で守る |

## 5. 音声を耳で確かめる（V）— 人が判定する

機械は「何と読んだか」までしか判定できない。抑揚・間・平坦さは、聞いた人が判定する。制作側の AI は音声を聞けないので、**この欄は AI が ✓ を付けない**。

| 番号 | 合格の条件（聞いた人が はい／いいえ で答える） |
|---|---|
| V1 | 人名・社名・商品名が、台帳の読みどおりに聞こえる |
| V2 | 数字（西暦・金額・割合・単位）が、画面の表記どおりに聞こえる |
| V3 | 文の途中に不自然な切れ目・息継ぎが無い。文と文の間が詰まりすぎていない |
| V4 | 抑揚が平らすぎる文・語尾が同じ調子で続く箇所が無い |

- レビュー便（Drive）で聞いた人が、`quality_record.md` の「5. 耳で確かめる項目」に、✓／✗ と気づいた箇所（時刻）を書く。Issue #2 に書いてもよい（制作側が記録に写す）。
- ✗ が付いた箇所は、型を R8（BAD）か A の基準に足して、次から機械で止める。
- 声の設定（話速・抑揚の強さ・文の間）を変えるときは、設定ごとのサンプルを作ってレビュー便に置き、耳で選んでもらう。数値だけで決めない。

## 6. note 記事（N）

道具：`_tools/checks/verify_note.py`（既存の構造検査に加えて）

| 番号 | 合格の条件 |
|---|---|
| N1 自分の呼び方 | 本文に「自社」「弊社」「当社」が無い。書き手は「自分」。読者の会社は「あなたの会社」「自分の会社」 |
| N2 タイトルの数字 | タイトルに算用数字が1つ以上ある |
| N3 対象の絞り込み | 記事の末尾に `<!-- 対象読者: 誰向けか｜キーワード -->` があり、キーワードのどれかがタイトルか冒頭300字にある |
| N4 冒頭の価値 | 最初の見出しより前（有料記事は `<!-- 有料ライン -->` より前）に、「数字＋単位」が1つ以上あり、読者の得を言う文（〜がわかる・〜できる・理由・手順）がある |
| N5 定型句 | A7 の定型句が無い |
| N6 語尾 | 同じ語尾が4文以上続かない |
| N7 数字の出どころ | 本文の数字が、対応する回のナレーションにある。記事で足す数字は `<!-- 追加の数字: 値｜URL1｜URL2 -->` に2ソースを書く |

## 8. 実施記録の読み方

`<回のフォルダ>/quality_record.md` には、次が入る。

1. 固有名詞（表記・読み・種別・確認ソース・確認日）
2. 読み検査：ビルド前（原稿）とビルド後（実際に音声になった読み）
3. 数字の確認
4. AI臭さ検査と実測値
5. 耳で確かめる項目（聞いた人が記入）

末尾の「機械検査の結果：PASS」が、その動画が1〜4の全項目に合格したことを示す。旧基準の回は「△（参考）」と表示される。
