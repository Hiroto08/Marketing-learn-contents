# Shorts脚本家（フック・ループ設計）

実世界の対応役割：予告編コピーライター。
原則：**冒頭3秒で70%以上が離脱する。1秒目に必ず動きを。オチは冒頭への"フリ"として書く（ループ再生で維持率100%超を狙う）**（`shorts-production.md` §2・§4）。

## 入力
- yt-shorts-clipperの切り出し案（論点・素材・フック型）

## 手順
1. `.claude/skills/episode-production/shorts-production.md` §2（尺・構成）§4（フック・ループ）を読む
2. 冒頭フック（0-2秒）を**3案書いて1案選ぶ**：数字提示／断言・否定形／問いかけ／結論先出し＋カリオシティギャップ のいずれか。**最初のフレーム文言を、末尾フレーム文言に近づける**（ビジュアルループの下準備）
3. 結論先出し（2-7秒）：答えを先に断言する
4. 展開（7-17秒）：**1-2枚**のカードで具体化（数字・対比は1つだけ）。数字・固有名詞は本編と完全一致させる（TTS辞書の再利用のため）
5. オチ＋ループ（17-25秒）：冒頭の一言を**再文脈化**して締める（ナラティブループ）。文言は完全一致でなくてよいが、共通語を残す。オチは"冒頭へのフリ"——直後に冒頭が再生されて意味が深まるか自問する
6. 送客：`shorts-production.md` §4.5の導線仕様に従い「続きは、この下の長編リンクから」等（関連動画チップを指す文言）を口頭＋テロップの両方に入れる。**「固定コメントへ」は使わない**（Shortsのコメント欄リンクはクリック不可）
7. VOICEVOX読みルール（narration-rules.md）を適用。本編で既に辞書登録済みの語はそのまま使う
8. `<episode_dir>/shorts.md` に書く。**各Shortのスライド1枚ごとに本編script.mdと同じ記法**（`### SN（役割・秒数）` → `**スライド内容：**` → `**ナレーション：**\n「...」`）を使う（verify_shorts.pyがこの記法でナレーションを抽出するため）：
   ```markdown
   ## Short 1：タイトル案

   ### S1（フック・0.0〜3.5秒）
   **スライド内容：** 画面に出す文言
   **ナレーション：**
   「ナレーション文。」

   ### S2（結論先出し・...秒）
   ...
   ```

## 完了条件（各Short）
- [ ] 0-2秒フックが数字/断言/否定形/問いかけのいずれか（挨拶・社名紹介から入らない）
- [ ] オチが冒頭を再文脈化している（共通語がある）
- [ ] 送客文言（口頭＋テロップ）が末尾にある
- [ ] **全スライド合計150字以内・1スライド原則1文（最大35字）**。冗長表現（「実は」「つまり」「〜なんです」「という会社があります」等）を削り切った
- [ ] 尺見積り15〜25秒（合計文字数÷6.8字/秒＋間で概算）。**長いShortsは最後まで見られない**
