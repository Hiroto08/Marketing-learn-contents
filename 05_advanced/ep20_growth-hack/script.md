```
【見出し】2008年・Dropbox——良い製品なのに広げられない

【見出し】発想の転換——広告費を「製品の機能」に変える
【キー】友だちを招待すると、招待した人も、された人も、両方に容量プレゼント
【対比】外にお金を払う広告 ／ 中に組み込む紹介（両者にメリット）
【注記】PayPalの紹介ボーナスを参考にしたと言われる
```

**アニメーション：** 見出し → 両者プレゼントのキー → 外の広告 vs 中の紹介 の対比 → 注記

**ナレーション：**
「そこでハウストンさんは、発想を切り替えます。広告会社にお金を払うのをやめて、そのぶんを、製品の中の仕組みに変えたんです。中身はこうです。友だちを招待すると、招待した人にも、された人にも、両方に無料の保存容量をプレゼントする。外の広告にお金を払うのではなく、紹介という機能を製品の中に組み込む。しかも、誘う側も誘われる側も、どちらも得をする形にした。ここが肝でした。」

### スライド 5：ケース③ 仕組みが回り出す——招待の置き場所（1:52〜2:24）

**スライド内容：**
```
【見出し】どこで誘うか——タイミングの設計
【フロー】登録直後に招待を促す → 容量が足りなくなった時にまた促す
【キー】欲しい気持ちが一番高い瞬間に、招待ボタンを置く
【数字】両者に500メガバイト。招待は月280万件に
```

**アニメーション：** 見出し → 2つのタイミングのフロー → キー → 数字（500MB／月280万件）

**ナレーション：**
「ただ機能を付けただけでは、人は誘いません。うまかったのは、置き場所です。使い始めた登録の直後と、保存容量が足りなくなった、まさにその瞬間に、招待をそっと促した。容量が欲しい気持ちが、一番高まっている所に、招待ボタンを置いたわけです。もらえるのは、両方に500メガバイト。すると、利用者みずからが友だちを誘い始め、その招待は、月に280万件にまで達しました。」

### スライド 6：ケース④ 結果——15ヶ月で40倍（2:24〜2:56）

**スライド内容：**
```
【見出し】結果——広告に頼らず自走した
【数字】15ヶ月で 10万人 → 400万人（約40倍）
【数字】新規登録の35%が紹介経由／登録数は恒久的に60%増
【キー】お金でなく、仕組みが客を連れてきた
```

**アニメーション：** 見出し → 10万→400万の伸び → 35%・60%の内訳 → キー

**ナレーション：**
「結果は、劇的でした。利用者は、15ヶ月で10万人から400万人へ。およそ40倍です。ピーク時には、新しい登録のうち、実に35パーセントが紹介経由。紹介の仕組みは、登録数そのものを、恒久的に60パーセント押し上げました。広告費をほとんど使わずに、です。つまり、お金が客を連れてきたのではありません。仕組みが、客を連れてきた。のちにこのやり方は、グロースハックと呼ばれるようになります。」

### スライド 7：リフック①——変えたのは広告費ではない（2:56〜3:22）

**スライド内容：**
```
【リフック】この会社が変えたのは、広告の“額”ではない
【転換】成長を、製品の外（広告）から、製品の中（仕組み）へ移した
【キー】広告は使えば消える。仕組みは、放っておいても回り続ける
【問い】あなたの成長は、止めたら消える広告に頼っていませんか
```

**アニメーション：** リフック文 → 外→中 の転換図 → キー → 問いのバナー

**ナレーション：**
「ここで、大事な整理をします。ドロップボックスが変えたのは、広告に使う金額では、ありません。成長させる場所を、製品の外側にある広告から、製品の内側にある仕組みへと、丸ごと移したんです。広告は、お金を払っている間だけ客を運び、止めれば消えます。いっぽう、製品に組み込んだ仕組みは、放っておいても回り続ける。あなたの会社の成長は、止めたとたんに消える広告に、頼りきりになっていませんか。」

---

### スライド 8：原則① まず「漏れ」を測る——AARRR（3:22〜3:54）

**スライド内容：**
```
【見出し】原則①——増やす前に、どこで漏れているかを測る
【AARRR】獲得 → 活性化 → 継続 → 収益 → 紹介（頭文字でAARRR＝海賊指標）
【キー】数を追わず、段階ごとの通過率を見る
【注記】提唱はDave McClure（2007）。成長の共通言語
```

**アニメーション：** 見出し → AARRRの5段階が左から出現 → キー → 注記

**ナレーション：**
「では、原則です。1つめ。むやみに増やす前に、まず、どこで人が漏れているかを測ります。使うのは、AARRR、通称、海賊指標です。お客さんは、獲得、活性化、継続、収益、紹介、という5つの段階を通っていく。この頭文字を取って、アーとつなげてAARRRと読みます。2007年にデイブ・マクルーアさんが示した、成長の共通言語です。全体の人数ではなく、段階ごとに何パーセントが次へ進んだか、その通過率を見る。これが出発点です。」

### スライド 9：原則② 一番効く1か所に集中する（3:54〜4:26）

**スライド内容：**
```
【見出し】原則②——一番の漏れ、1か所だけを直す
【たとえ】穴の空いたバケツ：注ぐ量より、大きい穴を塞ぐほうが効く
【キー】全部やろうとしない。ボトルネックを1つ選ぶ
【対比】獲得を増やす（水を足す）／ 継続を上げる（穴を塞ぐ）
```

**アニメーション：** 見出し → 穴あきバケツの図 → キー → 水を足す vs 穴を塞ぐ の対比

**ナレーション：**
「2つめ。測った5段階の中から、一番大きく漏れている所を、たった1か所だけ選んで直します。イメージは、穴の空いたバケツです。下に大きな穴が空いているのに、上から水をどんどん足しても、意味がありません。それより、一番大きい穴を塞ぐほうが、ずっと効きます。ドロップボックスにとって、その穴は、獲得コストの高さでした。だから広告を足すのをやめて、紹介という穴の塞ぎ方を選んだ。全部を同時にやろうとしない。一番効く1か所に、絞る。これが2つめの原則です。」

### スライド 10：原則③ 成長ループを作る（4:26〜4:58）

**スライド内容：**
```
【見出し】原則③——一度きりでなく、回り続ける形にする
【ループ】使う → 招待する → 新しい人が増える → その人がまた招待する
【キー】出口（紹介）を、入口（獲得）につなげると自走する
【条件】誘う側・誘われる側の両方にメリットがある
```

**アニメーション：** 見出し → 4ステップの円環ループが回り出す → キー → 両者メリットの条件

**ナレーション：**
「3つめ。直し方を、一度きりの施策でなく、ぐるぐる回り続ける形にします。これを、成長ループと呼びます。人が製品を使う。使う中で友だちを招待する。新しい人が増える。その新しい人が、また別の友だちを招待する。AARRRの出口である紹介を、入口である獲得に、つなげてあげる。すると、外から押さなくても、成長が自分で回り始めます。回すための条件は、1つ。誘う側にも、誘われる側にも、ちゃんとメリットがあること。片方だけが得をする仕組みは、続きません。」

---

### スライド 11：図解——AARRRファネルと成長ループ（4:58〜5:30）

**スライド内容：**
```
【見出し】1枚で見る——漏れを塞ぎ、ループで回す
【左】AARRRファネル：獲得→活性化→継続→収益→紹介（各段の通過率）
【右】成長ループ：紹介 → 獲得へ矢印を戻す
【キー】測って（ファネル）、塞いで、つなぐ（ループ）
```

**アニメーション：** 左のファネルが上から積み上がる → 一番細い段が赤く点滅 → 右のループへ紹介から矢印が戻る

**ナレーション：**
「3つの原則を、1枚の地図にまとめます。左が、AARRRのファネル。獲得から紹介まで、5つの段が縦に積まれ、それぞれに通過率が付いています。一番くびれている段が、あなたのボトルネック。そこを塞ぎます。そして右。塞いだうえで、一番下の紹介から、一番上の獲得へと、矢印を戻してあげる。これが成長ループです。測って、塞いで、つなぐ。この3つがそろって初めて、広告に頼らない成長が回り始めます。」

### スライド 12：リフック②——キャンペーンをやれ、ではない（5:30〜5:56）

**スライド内容：**
```
【リフック】ここまでの話は「紹介キャンペーンをやれ」ではない
【核心】穴の空いたバケツに、いくら人を注いでも下から漏れる
【部分回収】まず継続の穴を塞ぐ → それからループで注ぐ、の順番
【問い】あなたはいま、水を足す側？ 穴を塞ぐ側？
```

**アニメーション：** リフック文 → バケツに水を注ぐが漏れる → 「順番」の強調 → 問い

**ナレーション：**
「ここで、勘違いを1つ、つぶしておきます。今日の話は、とにかく紹介キャンペーンをやりましょう、という話では、ありません。むしろ逆です。継続に大きな穴が空いたまま、紹介でどんどん人を注いでも、その人たちは下から漏れていくだけ。お金と評判を、すり減らします。だから順番が大事です。まず一番の穴を塞ぐ。それから、ループで人を注ぐ。あなたはいま、水を足す側に立っていますか。それとも、穴を塞ぐ側ですか。」

### スライド 13：適用① 自社のAARRRを1枚に書く（5:56〜6:28）

**スライド内容：**
