# Opus での試作確認（2026-11-13）

社長指示（チャット・11/13）：「Opusで1本試作して確認して」。
モデルを Opus（`claude-opus-5-5`）に切り替え、`yt-expression` スキルの手順1〜5だけを見て、Short を1本作った。
狙いは「Fable が設計したスキルと道具で、別のモデルが同じ品質の動画を作れるか」の確認。

- 題材：u09（コストコのホットドッグ・5枚・約24秒）。**予約済みの回なので、写し（`_prototypes/expr_v1/pipeline_test/`）で作った。** YouTube にも予約にも触れていない。
- コマンド：`EXPR_FORCE=1 bash _tools/pipeline/run_shorts.sh <写し>`（本番と同じコマンド。試作なので日付の関門だけ外した）
- 映像意図：`_tools/expression/selftest/u09_visual_plan.json`（selftest の3本目に加えた）

## 1. 結果

| | 結果 |
|---|---|
| 機械検査（S1〜S7・M1・M2・V4・D1〜D3・P1〜P9） | 全項目 合格（最終ビルド） |
| 目での確認（スキル §5） | 合格（最終ビルド） |
| 最初のビルドの時点 | 機械検査は1項目（V4）不合格。目で見ると、ほかに5つの不具合 |
| かかった手直し | ビルド4回。スキルの表の穴 3つ・道具の不具合 6つを直した（下の表） |

**結論：スキルの手順と型の表は、Opus でもそのまま使えた。ただし、最初の1本では「機械検査は通るが、目で見るとおかしい」不具合が5つあった。§5（目で見る確認）を省くと、そのまま出ていた。** 見つけた穴と不具合は全部直し、同じ型の不具合が機械で止まるよう検査を足した。

## 3. 見つけたことと直したこと

| # | 見つけたこと | 見つけ方 | 直したこと |
|---|---|---|---|
| 1 | スキルの表に「前のスライドの数字と比べる」行が無い。検査 P5 も、前のスライドの数字を「台本に無い」と止めていた | 表を当てて | 表の3に追記。P5 は compare_bars だけ、1つ前のスライドの数字も認める（台本に無い数字は引き続き止まる） |
| 2 | 表の「quote」が「」のある文に限られていた | 表を当てて | 「〜は言った。」の直後の文も発言として quote |

| 4 | 写真の reset が実装されていなかった（棒グラフだけ）。最後のコマが寄ったまま＝ループで絵が跳ぶ | 機械検査 V4 | 写真の reset：最後の約1秒で寄りを戻す |

- 写真（ホットドッグ）は、表現コードの色調（灰色＋紺）にすると食べ物らしさが薄れる。原寸では何か分かるので、今回は変えていない。食べ物・商品の写真を多く使うなら、色調の決まりを見直す余地がある（**提案**。仕様の変更なので決裁が要る）。
- Wikimedia Commons が 429（混雑）を2回返した。スキルどおり10分待ってやり直し、取れた。制作バッチで写真を多く取るときは、時間に余裕を見る。
