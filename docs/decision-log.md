### 2026-11-05（夜）CMO レビュー（Issue #1）とレビュー便（Issue #2）への対応

- **レビュー便の試行送付に成功**：ユーザーが DRIVE_REFRESH_TOKEN を登録したので、u01 を Drive の「マーケラボ レビュー便」へ送った（`1wnBXeNeWyjmxA00a1HpcxMSNr3X2LHDu`）。Issue #2 に報告済み。
  - 環境変数はセッションの起動時にしか読まれない。そのため、登録直後は送付用の別セッションを立ち上げて送った。
  - 残り15本（u02〜u14・c01・c02）は 11/6 17:10 の作業でまとめて送る。
- **レビュー便の重複判定を YouTube の videoId 基準にした**（私の判断）：同じ動画を別の環境で作り直すと mp4 のバイトが変わるため、ファイルの中身では重複を判定できない。

- **新事例を採る条件（CMO 指示）**：「仕組みの核がある」「数字が2つの情報源で確かめられる」「数字の落ちがある」の3つ。満たさなければハイブリッド型（古典が主役で、新事例は冒頭のフック）にする。鮮度欄に型も書く。→ `s2_ura/README.md` §2
- **題材集めの情報源を4種類に固定（CMO 指示）**：企業の公式発表・決算／規制当局／業界メディア／SNS で先に話題になったもの（要裏取り）。→ README §2・作戦 §5.1
- **差し込み枠は採用（私の判断）**：金曜を差し込み枠にし、木曜のジョブが速報題材（無ければプール上位）で埋める。予約を3〜5日先までにしているので、金曜を1日前に埋めても制作は間に合う（Short 1本は台本からアップまで約30分）。採否と理由は毎週 `s2_ura/insert-slot-log.md` に1行書き、週次分析にも出す。
- **自社事例を候補に登録（CMO 指示）**：なまえバトルの広告配分変更の結果を、12月のケースファイル候補として `s2_ura/topic-pool.md` に入れた。数字が確定してから組む。
- **CMO からの題材候補の受け取り**：月・木のジョブが GitHub の Issue を見て、題材プールに入れる。
- **判定に流入経路を足す（CMO の注文）**：weekly_stats で、時事・ハイブリッド・古典ごとの「Shorts フィード／検索／その他」の割合を出す。
- **関連動画の設定は統合運営側が代行（社長決裁）**：本編の公開後にバッチで設定される。こちらでの手動設定は不要。→ `docs/autonomous-operation.md` §4・README §4（24話側は「確認待ち」に入れた）
- **レビュー便**：
  - 完成 mp4 を非公開アップと同時に Drive の「マーケラボ レビュー便」に上げる。`upload_youtube.py` から自動で呼ぶようにした（`upload_review_drive.py`）。
  - 動画の中身を差し替えたときは、新しく非公開アップする。旧版は削除せず、公開予約だけ外して非公開で残す。そのうえで、新旧の videoId を Issue #2 に報告する。
  - ただし Drive の権限があるトークンがまだ無いため、送付は止まっている（「確認待ち」の1行目）。→ README §5
